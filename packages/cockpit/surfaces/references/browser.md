# Browser access and evidence

<!-- cockpit:verified version=0.0.0 -->

The rendered browser skill records each harness/version, measurement date, transport spelling,
and declaration strength. Historical measurements seed declarations. Current callable status
remains `human_needed` until the operator records a harmless invocation and a discovered broken
control on the current executable. An unsupported version or transport is `unavailable` and
emits no transport control. A declaration, a synthetic receipt, and a passing source test each
establish different facts; none proves a native browser invocation.

Use the shared headless connection for the configured browser and the issued runtime posture. The pinned
MCP image connects to the checking proxy endpoint. The optional CLI comes only from the exact
`@playwright/test` package named by the project lock identity, with authenticated installed manifest, entry-point bytes and npm lock bytes. Other lock
formats currently make this transport unavailable to this renderer. Never substitute a standalone CLI package. Prefer the eligible CLI for
identity-sensitive or concurrent work. Use a headed browser only as a separate debugger.

For real authentication, use mode-600 stored state minted from seeded users and the declared
serialized or per-worker policy. Perform sign-in through a transcript-safe channel. Keep
credentials, state contents, page content and production data out of transcripts and tracked
files. Bypassed authentication makes sign-in and persona selection inapplicable. Hostname
posture needs browser-side resolver rules; port posture makes resolver rules inapplicable.

Shared MCP approval enables a server; browser tool preapproval is a separate decision. Only
isolated empty or seeded data without production reach can be eligible. Restored data,
shared data and production-reaching servers never qualify. The measured Codex transport needs
per-server `default_tools_approval_mode = "approve"`; when eligibility is absent its declaration
is omitted. Other unmeasured approval controls are omitted. No browser setting changes a
guard decision or authorizes its own launch.

An independent grader retains browser tools. File read-only restrictions concern repository
files. Browser driving can change product state, so product-state restraint is instructed.
Do not narrow the grader's tool access to manufacture file safety.

For a native paired probe, use the rendered exact tool invocation against `about:blank` or
the pinned test-package remote `cli attach`, `goto about:blank`, and `close` commands. Place a deliberately malformed declaration beside
the candidate, retaining both byte identities. Verify the harness actually names and rejects
the broken file; silence does not prove discovery. Capture the current executable/version,
package identity, bounded version/help command results, rendered bytes, exact invocation,
observation, timeout/output bounds and cleanup readback. MCP receipts record the native config
loader and installed bytes; CLI receipts record harness shell execution and the pinned CLI
config preparation, without inventing a harness config flag. Bind reset and filesystem readback
to the issued cockpit directory, after both observations complete. The receipt validator checks these bindings only; an authenticated operator
must establish the observation's provenance and semantic support before any promotion.

Every transport root comes from the issued runtime reset inventory, including auth and
debugger roots. After recording fixture artifacts for every root, replay the public reset and
confirm the artifacts are gone while the unregistered negative control remains. Reject the
negative control as unregistered. A reported cleanup flag alone is not filesystem proof.
Keep all native probe execution and operator acceptance held until the authorized operator pass.

CLI packaging and remote-session syntax are documented in the upstream
[package manifest](https://github.com/microsoft/playwright/blob/main/packages/playwright-test/package.json)
and [CLI dispatcher](https://github.com/microsoft/playwright/blob/main/packages/playwright-core/src/cli/program.ts),
with [remote command handling](https://github.com/microsoft/playwright/blob/main/packages/playwright-core/src/tools/cli-client/program.ts).
These references describe syntax; the installed pinned package remains the runtime authority.
