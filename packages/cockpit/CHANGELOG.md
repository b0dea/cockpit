# @b00dea/cockpit

What changed in each release of cockpit, newest first, for someone deciding whether to upgrade:
what breaks, what to do about it, and what is new. Changesets writes each entry from the
changesets merged since the previous release. An entry that needs more than `cockpit sync` ends
with a line starting `Upgrade:`; the [changeset guide](../../.changeset/README.md) defines that
convention.

Versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). The public surface a
major version protects is the CLI's commands and flags, the <!-- cockpit:ref consumer=cockpit.toml --> `cockpit.toml` schema, the generated
file layout, and the overlay contract. Deprecation and migration rules are in the
[release policy](../../docs/release-policy.md).

## 0.1.0

### Minor Changes

- 0067955: Initial public release.
  
  - One `cockpit.toml` is the policy and the product declaration: sibling repositories, ports, guards, MCP servers, autonomy and work. `cockpit sibling add|remove` edits the repository list and `cockpit tool add|remove` edits `[surfaces] tools`, which defaults to Claude Code, Codex CLI and OpenCode.
  - `cockpit sync` writes the matching instructions, skills, subagents, hooks, permissions and MCP entries for each listed tool, with `--dry-run` previews, and `cockpit check` fails when a generated file no longer matches, locally or in the `cockpit-check` GitHub Action. `sync --adopt <path>` moves a team's existing agent settings file into cockpit and merges it with the generated version.
  - One guard policy refuses pushes to protected branches, reads and edits of declared environment files and secrets directories, and commands against declared hosted databases or vendor hosts. `[[guards.deny]]` and `[[guards.allow]]` add your own command rules. The hook is installed for Claude Code, Codex CLI and OpenCode, fails closed, and also denies agent writes to `.npmrc` and to cockpit's own policy and records. Codex runs the hook only after a person trusts it once per machine; `doctor` and `check` report `CODEX_HOOK_UNTRUSTED` until then. `cockpit selftest` checks that each tool enforces the generated controls, and the capability matrix records dated measurements.
  - Sibling repositories' guides are copied into the root instructions, and the Claude Code and Codex hooks run `cockpit check` as a session starts.
  - `cockpit init` starts in the repository it runs in: a single product repository gets an in-repo cockpit, every listed tool gets the `cockpit-setup` skill, and the interview marks every value it inferred or defaulted. `init` writes a commented `[work.gates]` and `[autonomy]` block, and `--registry` turns an existing shell-script setup into a draft. `init --scaffold-compose` writes one plain `compose.yml` for a small app, once.
  - cockpit runs your own Compose files and generates none. `setup`, `up`, `session`, `sleep`, `down`, `reset`, `preflight`, `doctor` and `logs` run the stack on your live checkouts, with port leases and holders so one agent cannot stop another agent's stack. `environment.seed` with `resettable_volumes` fills and refills the data, and `reset` needs a person by default. `down` and `reset` use only a local Docker context, and `cockpit runtime measure` records the local runtime for this machine only.
  - `[autonomy]` and `[work.gates]` say who may pass each step. Everything defaults to `agent` except `[autonomy] reset` and `mcp_approve`, which default to `person`. `check` and `doctor` report a policy weakening nobody has confirmed, and the guard denies an agent's edit of the policy.
  - Each repository's tracked `.env.schema` is validated with Varlock when it is installed, without reading values. MCP servers are enabled only for the digest recorded under `[mcp.approved]`.
  - Work orders are `workorders/<id>.md` with YAML front-matter. `[work] grading` is `independent` (an evaluator in the first usable of `work.evaluators`, any of Claude Code, Codex CLI or OpenCode, reruns the checks and grades each criterion), `checks` or `self`. `cockpit grade --criteria <file>` grades uncommitted work with no order, and `work verify` checks the records in CI.
  - Declared test stages and gates run with `cockpit test-run`, and only a complete passing gate reports PASS.
  - `cockpit browser drive` and `browser screenshot` visit the application's declared routes with a local browser. `browser.endpoint` may name a loopback browser service from your own Compose file, which publishes the Playwright MCP declaration and the `cockpit-browser` skill. cockpit runs no browser service and no debugger.
  - `cockpit upgrade [<version>] [--dry-run]` moves the exact pin and re-runs `sync`.
  - Teams share one cockpit: the root `package.json` pins the exact cockpit version, `check` refuses a different running version, and cockpit manages its own block in `.gitignore`.
  - Diagnostics name what failed, why it matters and the fix. The package ships the user guide under `docs/` and skills that tell agents how to set up, explain, fix and work in a cockpit; install the adoption skill with `npx skills add b0dea/cockpit --skill adopt-cockpit`.
  - Runs on macOS and Linux. Native Windows is refused at startup; WSL2 should behave like Linux but is untested.

### Patch Changes

- be5adb5: Every `[autonomy]` and `[work.gates]` decision now defaults to `agent` except `reset` and `mcp_approve`, which default to `person`. The `[autonomy] preset` key is removed, and `cockpit init` writes the defaults as a commented block so one can be flipped to `person`.
- bc8fa52: Browser screenshots can no longer be committed by accident, and the first screenshot no longer needs the artifact directory to exist.
  
  - `cockpit sync` adds every `environment.generated_host_paths` entry, which includes the browser artifact roots such as `.browser/cli`, to the managed `.gitignore` block.
  - The browser screenshot command creates its artifact root, including a missing parent such as `.browser`, before writing into it.
  - When no `browser.harnesses` row is at a measured version, the work application's refusal names the declared and measured harness versions and the `sync` command to run after fixing `cockpit.toml`.
- 3cd8bbf: `cockpit browser debugger` is removed: it refused in every configuration because the headed browser runner it needed is no longer rendered. `browser drive` and `browser screenshot` are unchanged.
- cfb2f97: `browser.endpoint` is no longer refused outright: it must be a loopback `ws://` address whose port exactly one service in `environment.compose_files` publishes on loopback, otherwise sync refuses with `GENERATED_BROWSER_ENDPOINT_UNPUBLISHED`.
- ffb5ba5: A `browser.endpoint` published by the project's own Compose service now publishes the Playwright MCP server and the `cockpit-browser` skill at sync, without a cockpit port lease.
- 525477b: Removed the browser native-transport receipt validator and the probe specifications it consumed: no command ran or recorded them, and a valid receipt left every transport `human_needed`, so the check changed nothing. The capability matrix now lists browser native transports under "Without a measurement", and the browser reference no longer mentions a record validator.
- d075210: Browser operations reach only what they should.
  
  - Browser operations block requests to loopback and resolver-mapped hosts outside the application origin. Redirects that the browser follows are not routed, so they are not blocked.
  - `up` and `sync` name an unparseable browser project `package.json` or lockfile with the line and column, and no longer quote its contents.
- 2ec827b: `[browser]` drops the fields only the removed browser runner read: `images.runner`, `artifacts.runner`, `artifacts.debugger` and `headed`. The runner script is no longer shipped, and `cockpit browser debugger` refuses with the reason, since nothing can prepare a headed debugger. `browser drive` and `browser screenshot` keep working through the local project client.
- 1f884bc: The harness registry no longer records Claude Code, Codex and OpenCode as awaiting a native paired probe dated before their guard firing and instruction loading were measured; what it records as open for them is the person's review of the rendered skills, which the capability matrix shows.
- 01d2003: `cockpit check` now fails with `POLICY_WEAKENING_UNCONFIRMED` while `[work]`, `[work.gates]` or `[autonomy]` in `cockpit.toml` is weaker than the policy the last sync recorded, instead of leaving the weakening to surface only at the next sync.
- 6fdd9f4: `check` fails with `GENERATED_HOST_PATH_UNMOUNTED` for an `environment.generated_host_paths` entry that no service bind-mounts, naming the entry and how to fix it. In compose-first mode `up` already refused such a stack, and now `check` says so first. An entry inside a bound directory, such as a sibling mounted whole, reaches the container through that bind and counts as mounted; compose-first `up` no longer refuses it either.
- b4e7209: The generated `.claude/settings.json` now allows, by prefix, the cockpit commands the shipped skills tell an agent to run and the guard admits, such as `test-run`, `check` and `doctor`. Claude Code's default mode previously refused them in a headless session. Person-only commands such as `sync`, `down` and `work accept` still prompt, the guard hook still decides first, and Claude Code applies the rules only once a person has trusted the workspace.
  
  The shipped Fix procedure is now a direct fix: run the declared gate before and after the change, with no intake or source audit. The guides say which cockpit commands a Codex user runs outside Codex's sandbox, that the person commits the cockpit repository, and use `--target <tool>` instead of one tool's target.
  
  The vendor-specific identity-provider starter is no longer written into every cockpit; its two general lessons (confirm the roles the provider instance exposes, sign in through the provider's own test helper without a second token helper) are now in the test-data reference.
- 616736f: Several runtime and lifecycle reports now say what actually happened.
  
  - When Docker Engine or Docker Compose prints a version with no numeric X.Y.Z core, `up` and `runtime measure` say which tool printed what, and the fix is to install a release that prints one. The fix used to be "start the configured container runtime", which was already running.
  - When `up` refuses because a running stack's declaration changed, the message names the file that changed (for example `compose.yml`, or `[ports]` in `cockpit.toml`) instead of always naming `cockpit.toml`.
  - When a long-running command keeps only the tail of its output, the tail now starts at a whole UTF-8 character, so the first character is no longer garbled.
  - `logs` now works when Docker Compose prints a vendor suffix such as `2.29.7-desktop.1`. It used to refuse every read on such a runtime.
  - A file listed in `environment.generated_host_paths` is now ignored in the managed `.gitignore` block, as a directory there already was.
- 3bf2315: Running `dist/cli.js` through a symlinked package directory (npm link, workspaces) now runs the command instead of exiting 0 without output.
- 57a2ad7: The Codex `writable_roots` that `sync` writes for repositories beside the cockpit no longer depend on the directory you run it from. Run from inside a sibling repository, `sync` used to write a root that pointed at the wrong place, and `check` then reported `.codex/config.toml` as drifted depending on where it ran.
- f416f24: cockpit runs your own Compose files and no longer generates one.
  
  - `[environment.generated]` and `sibling[].derives.generated` are gone, and with them the generated services, dependency volumes and installs, vendor stubs and their TLS probes, the `empty`, `seeded` and `restored` data modes, restore rewrites, persona outputs and `docs/cockpit/environment-decisions.md`. So are the rendered browser runner and its fields: `browser.resources`, `browser.runner_health_measurement` and `browser.images.runner.architectures` are unknown keys. A `cockpit.toml` that still sets one is refused; declare `environment.compose_files` and keep the stack in plain Compose. The new Compose patterns guide shows a vendor stub, a TLS front end and a data restore.
  - `environment.seed = { argv = [...], timeout_seconds = N }`, beside `environment.resettable_volumes`, is the command `up` runs once the stack is healthy, and again whenever one of those volumes is newer than the last successful seed, such as after `reset`. A seed that fails refuses with `DATA_SEED_FAILED`, leaves the stack up, and runs again on the next `up`. Editing it leaves a running stack alone.
  - `npx --no cockpit init <cockpit root> --scaffold-compose <app dir> --port <port>` writes a starting `compose.yml` for a small app once, with an optional `--with postgres,redis`, and never replaces an existing Compose file.
  - A compose-first `up` now refuses with `MACHINE_MEMORY_BELOW_FLOOR`, `MACHINE_CPU_BELOW_FLOOR` or `MACHINE_DISK_BELOW_FLOOR` before starting anything on a machine below the declared `[environment.machine]` floor. Only a generated stack used to be held to it.
  - `examples/synthetic` is gone; the tutorial walks through `examples/compose-first`, and `examples/minimal` runs its own `compose.yml`.
- da3debb: Refusals from `sibling add`, `sibling remove` and `sync --adopt` when they cannot edit `cockpit.toml` safely now carry a fix: wait for another edit to finish and run the same command again, correct the option the message names, or make the change by hand and preview it with `sync --dry-run`. The printed `--config` path in a `sibling` fix is the one the command was given, and the JSON invocation record names it.
- 9e4c9af: Sync reads `cockpit.toml` through the ordinary anchored file read, and its unreadable-file refusal is now `GENERATED_CONFIG_SOURCE_UNAVAILABLE`.
- a6b9a2c: A new Configuration essentials page covers the `cockpit.toml` tables a typical cockpit sets, each with a minimal snippet and a link to its full reference entry.
  
  The configuration reference is now one table per TOML table, listing every key with its type, default and constraints. Tables that recur, such as probes and provenance, are listed once and linked, and the JSON Schema is linked instead of printed, so the page is about a tenth of its former length.
- b65f142: Every `cockpit.toml` field now has an effect, or it is gone.
  
  - Removed `cockpit.guide`, which nothing read. A configuration that still sets it is refused as an unknown key, so delete the line.
  - A sibling guide declared under `guides` that does not exist, other than the default `CLAUDE.md` and `AGENTS.md`, now fails `sync` and `check` with `SIBLING_GUIDE_MISSING`. It used to link nothing and say nothing.
  - Browser driver versions accept a semantic-version pre-release, such as the Playwright alpha an MCP image bundles. The runner image must still match `browser.project.driver_version` exactly; the MCP image must share its major.minor.
- f7bbe8b: Every refusal to load `cockpit.toml` now carries a fix: a missing file names `--config` and `cockpit init`, an unreadable, oversized, non-UTF-8 or unparseable file says what to repair, and a schema mismatch points at the configuration reference. `[testing].native_hooks` may be left out and defaults to `{ install = "inspect" }`, as documented; a declared `native_hook_policy` still needs `native_hooks = { install = "explicit-native" }` beside it.
- 038d0aa: When `work.evaluators` is not set, `work grade` and `cockpit grade` now try the other listed agent tool first and the tool running the command last, detected from `CLAUDECODE` or `CODEX_THREAD_ID`. A declared list is used as written.
  
  `work grade` and `grade --criteria` accept `--evaluator <tool>` to grade one run with only that tool, with no fallback.
- 3669b51: `doctor` and `init` now say what the project still lacks for cockpit to work, before the first `up` and without guessing.
  
  - Before the first bring-up, while the stack sleeps, and (in `doctor`) for a cockpit that declares no runtime, `doctor` and `preflight` run every check that needs no running stack (Git state, sibling presence, the machine floor, the runtime measurement, the env schema, the generated surfaces) and report the rest as not applicable. `STATE_UNSEEDED`, `STACK_NOT_RUNNING` or `ENVIRONMENT_NOT_DECLARED` is listed first instead of replacing every check, and `preflight` still never passes in those states. A container runtime that is missing then is reported as `RUNTIME_UNAVAILABLE` with a fix.
  - `doctor --json` carries `result.readiness`, and the human report has one line per gap. It groups the reported diagnostics under the prerequisites cockpit depends on, each with why cockpit needs it and whether it is required (refused by the command that needs it) or recommended. Every `init` stop carries the same `result.readiness`, the preview included.
  - New warnings: `COCKPIT_NOT_INSTALLED` when cockpit is not installed in the cockpit root or the guard hook runs a copy outside it (every new cockpit, because `init` runs from a temporary install); `SIBLING_REMOTE_UNRECORDED` when a sibling is its own Git repository but `cockpit.toml` records no remote, so a teammate's `setup` cannot obtain it; `SECRET_FILE_TRACKED` when a repository commits a `.env`-style file, named by path only and never read. `init` also warns `SETUP_PATH_TYPE_INVALID` when the cockpit root is not in a Git working tree.
  - `check` and `sync` report a declared sibling that is absent as `SIBLING_MISSING`, with how to obtain it, instead of `GENERATED_SIBLING_ROOT_INVALID` with a raw `realpath ENOENT`.
  - The setup skill's onboarding procedure walks the human through each readiness gap and asks before touching a product repository. The documented `init` stops now include `STATE_UNSEEDED`.
- 3bfa530: `doctor` now exits 2 when `cockpit.toml` is missing or invalid, instead of exiting 0 with an unavailable verdict. Its human output is a short report, one line per area with the commands that show the detail, instead of thousands of lines, and `--json` reports whether the generated files are current (`freshness.local` holds the check's kind, status and diagnostics) instead of embedding the complete check result.
- d3609e5: `doctor` warns `COCKPIT_LAUNCHER_UNPROVEN` when the guard cannot prove that `npx --no cockpit` run in the cockpit root starts the installed cockpit (a root `.npmrc`, a `bin` or `directories.bin` in the root `package.json`, or a `node_modules/.bin/cockpit` that is not npm's link), so every printed `npx` command would prompt, and Codex and OpenCode would refuse it. It runs the guard's own check and names `./node_modules/.bin/cockpit <command> --config cockpit.toml` when that spelling is still proven.
- 23e1e36: `doctor` reports the refusal `check` gives when it cannot check the generated publication (a published port outside `ports.bases`, for one), with its fix, instead of the surface-evidence findings that refusal makes unavailable.
- b7f0fde: `doctor` now reports a policy that `cockpit.toml` sets weaker than the one the last sync recorded, as `check` already does.
- fd3ad2f: `doctor` warns with `GUARD_SEARCH_PATH_RELATIVE` when the `PATH` it runs with holds a relative or empty entry, which makes the guard ask before every agent command, and names the entry; readiness lists it as `harness-path-absolute`.
- bbac384: The guard now denies reading, writing, removing, staging or linking any `.env` or `.env.*` file at any depth, declared or not; before, an agent's edit of an undeclared `.env` was allowed and `cat .env` only prompted. `.env.example`, `.env.sample`, `.env.template`, `.env.schema` and declared templates stay readable and writable, and recursive searches and Git content commands now treat those names as documentation too. The refusal points to `varlock run -- <cmd>` or the `.env.schema`. Claude Code's generated `Read` deny rules now cover `.env` and `.env.*` as well; because Claude applies a deny before any allow, its own Read, Grep and Glob tools also refuse the documentation names, which a shell `cat` still reads.
- ac05031: When the generated files no longer match `cockpit.toml`, for example after upgrading cockpit, `down` and `reset` still refuse rather than hand Compose a file cockpit did not render from the current declaration, but the refusal now says nothing was stopped and prints the whole recovery: run `sync`, then `down`.
- 6477cf3: The published `cockpit.schema.json` now holds `[mcp.approved]` server names, `[ports.bases]` names and generated `port_defaults` names to the same key patterns the loader enforces, so an editor flags a key `check` would refuse.
- 606f5d1: `grade --criteria` accepts an absolute path inside the repository, and refuses a path outside it with a message naming `--criteria` and the rule.
- 1cbc7ab: The guard now admits the read-only idioms agents use constantly, which headless Codex and OpenCode previously turned into refusals, and every remaining refusal names the command and says what to do instead.
  
  - `cd ./api && <command>` and `cd ./api; <command>` judge the command from the directory it runs in, under the same rules. After `;` or `||` a failed `cd` leaves the shell where it was, so the command is judged from both directories. A bare `cd api` is still refused, because both shells resolve it through `CDPATH` first; the refusal says to write `cd ./api`.
  - `echo` and `printf` without options are read-only, and `$?` in their arguments is the previous exit status, not dynamic command construction. A `$?` in any argument that could name a path still asks.
  - `sed -n <range>p <file>` reads like `cat`; any other sed command still asks.
  - `git rev-parse` and `git branch` with listing flags (`-v`, `-vv`, `-a`, `-r`, `--show-current`) are read-only, and `@{u}`, `HEAD@{1}` and `HEAD~1` are Git revisions, not brace or tilde expansion.
  - `git add <paths>` naming a guard control such as `.claude/settings.json` now asks like any other staging instead of being refused outright: staging writes the index, not the file. Committing still requires a person.
  - `git add -A`, `git add .` or a directory that contains `env/.secrets` or a declared environment instance is still refused, and the refusal now says to stage the changed files by name.
  - A command the guard does not admit now names itself, and says how to proceed: a person approves it or runs it in a terminal, tests run through `npx --no cockpit test-run`, and `[guards] allow` admits a command for good. A read outside the configured roots says so.
- 3ed866f: The guard now admits the commands the shipped skills and guides tell an agent to run, as exact profiles: `test-run` on a declared gate, the `work` subcommands without `--interactive`, `cockpit grade --criteria`, the preview of `work recover`, and, where `browser.request_preapproval` is set, `browser drive` and `browser screenshot`. A file these commands name, such as `--criteria`, is checked as a read, so a declared instance or `.secrets` file is denied and an undeclared `.env` prompts. Before, every one of them prompted, and Codex and OpenCode refused them. `--interactive`, `work recover --apply` and `browser debugger` still need a person, and the safety page says why for each.
- 7ef0e26: The guard asks Git what an `rg` search and a Git command would print, instead of refusing too much or too little.
  
  - A plain `rg needle` at the root of a project with a large ignored `node_modules` asked, and Codex and OpenCode turned that into a denial. The guard now asks Git which files the repository does not ignore, as ripgrep skips the rest, so a gitignored `.env` or dependency tree no longer blocks it; an untracked `.env.local` that is not ignored still asks, and `grep -r` still walks every file.
  - `git diff`, `git show` and `git log -p` printed a tracked `.env*` file, secrets file or declared instance without a prompt. They now ask while the repository's index holds one, unless limited with `-- <path>` to paths that hold none.
- d86a9e2: The guard now admits `jq` reading files as read-only, like `cat`, unless the filter reads the environment or a module, or the command writes.
- a5a1d6a: When the guard cannot inspect a path because the filesystem refused, its refusal now names the system error instead of only saying inspection failed.
- e414443: The guard lets agents read declared templates and search code, and protects the MCP wrapper scripts.
  
  - A sibling's declared environment `template` (such as `.env.example`) is readable. Undeclared `.env*` files still need approval, and declared instances are still denied.
  - A recursive search (`rg`, `grep -r`, OpenCode's grep) over a sibling or the cockpit root is allowed when no declared instance or `env/.secrets` exists below it. When one does, the reason names it so the agent can search a narrower path; Codex and OpenCode used to deny every such search with a generic reason.
  - Writing, removing or replacing a generated MCP wrapper script under `.cockpit/mcp/` is a hard denial, like the other guard controls.
- c29ebf7: The guard answers a default `rg` search faster in a checkout with large ignored directories such as `node_modules`, and stops asking about files ripgrep never reads.
  
  - Git now names each ignored directory once instead of listing everything inside it, so the check no longer grows with the size of `node_modules`. Its Git queries for one search, and for several searched paths, run together.
  - An `.ignore` or `.rgignore` file or a `.jj` directory inside an ignored directory no longer makes the guard ask: ripgrep does not enter that directory. The same entries in a directory ripgrep does enter still make it ask.
  - A tree or repository can hold up to 1024 environment files before the guard stops naming them, up from 256. Above that bound it still asks.
- 019c0ad: The guard no longer lets a recursive search or a shadowed command name read secrets without a prompt.
  
  - A recursive search (`rg`, `grep -r`, OpenCode's grep) is allowed only when a bounded walk of its tree finds no `.secrets` directory and no `.env*` file other than a declared template, and every other command in the call is read-only, so none can write one first. `grep -rn API_KEY .` used to print an undeclared sibling `.env.local` that `cat` would have stopped at. A tree too large to walk needs approval; the reason names what was found, so the agent can search a narrower path.
  - `rg -g`, `--glob` and `--iglob` are read-only only as `!` exclusions, because any other glob overrides ripgrep's hidden and ignore filters.
  - While the agent harness's `PATH` holds a relative or empty entry, no command is allowed without a prompt, since a file the agent wrote could run in place of a command or of the interpreter a path-spelled script starts by name. The reason names the entry; remove it from the `PATH` the harness starts with.
- 1e8c651: The guard no longer allows reads of a declared instance through these spellings:
  
  - A `cd` after `||` may not run while the `&&` after it still does, so in `pwd || cd ./src && cat config/active.instance` the `cat` is now judged from both directories and denied.
  - A newline after `&&`, `||` or `|` continues the list, so `pwd |` followed by a `cd` on the next line is refused like any `cd` in a pipeline.
  - `rg` falls back to the guard's own walk when a `.gitignore` holds a line Git and ripgrep may match differently, such as `[[:alpha:]]`, braces, a backslash escape, trailing whitespace, a `**` inside a path component or bytes that are not UTF-8; Git could ignore a file ripgrep then reads.
  - A path or `git -C` directory that leaves a symlink through `..`, such as `cat link/../active.instance`, is no longer judged by its spelling; it is treated like any symlink.
  - `env -C` with `$?`, `cd` or `env -C` with `..` after a directory name, `pushd`, `popd`, zsh's `chdir`, `builtin` and a zsh `=command` word are refused, since the guard cannot see the directory or path they expand to.
- 7c90129: The guard now authenticates and evaluates in one Node process instead of dispatching a second handler process per tool call, and it asks Git once per checkout instead of repeating identical probes. Run `npx --no cockpit sync` to regenerate `.cockpit/guards/bash-guard.sh`.
- c78cf3f: `SURFACE_STATE_CONFLICT` on a hand-edited generated file (a skill, `.claude/settings.json`, the text between cockpit's markers in `AGENTS.md`, or the OpenCode root group) carries its own fix: move the edit into `cockpit.toml` or a surface overlay, and ask the person who owns the cockpit before discarding it. A file cockpit has no record of writing gets a fix that asks the person before it is moved or deleted, and a team's own harness settings file names the `sync --adopt` command in the fix rather than in the message.
- d3d59a8: `init` shows the Compose port and healthcheck findings `check` would report for the drafted `cockpit.toml`, with the exact edit, before the draft is accepted; it still never edits a Compose file.
- a3d5ba1: `init` inside a product repository now recommends and, under `--accept-preview` or `--accept-defaults`, defaults to an in-repo cockpit instead of refusing.
- f323d50: A bare `cockpit init` now sets up the current directory for the default tools (Claude Code, Codex CLI and OpenCode). An explicit root and `--target` still choose otherwise.
- 0d7b90a: `init` no longer proposes values the schema rejects, and say where every inferred port base came from.
  
  - Proposed `[testing]` stage and gate ids now lead with their role (`test-api`, `targeted-api`, `full-api`, `affected-api`), so a repository whose directory name starts with a digit gets ids the schema accepts. A name too long to form a 64-character id is reported as a skipped inference instead of being proposed.
  - When `ports.bases` is read from several Compose files, the proposal names each file and the variables it publishes, including the files on both sides of a conflicting default.
  - A Compose file that publishes a literal host port, such as `"8080:80"` or `published: 8080`, is reported as a skipped inference that says to publish it from a variable with a default.
- 5fda3af: `init` now proposes more of what the product's own files already declare.
