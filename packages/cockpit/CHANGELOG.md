# @b00dea/cockpit

What changed in each release of cockpit, newest first, for someone deciding whether to upgrade:
what breaks, what to do about it, and what is new. Changesets writes each entry from the
changesets merged since the previous release. An entry that needs more than `cockpit sync` ends
with a line starting `Upgrade:`; the [changeset guide](../../.changeset/README.md) defines that
convention.

Versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). The public surface a
major version protects is the CLI's commands and flags, the <!-- cockpit:ref consumer=cockpit.toml --> `cockpit.toml` schema, the generated
file layout, and the overlay contract. Deprecation and migration rules are in the
[release policy](../../docs/release-policy.md).

## 0.1.10

### Patch Changes

- 37c0989: `cockpit sync --interactive` refuses to take a confirmation inside an agent tool's session, where Claude Code sets `CLAUDECODE`, Codex `CODEX_THREAD_ID` and OpenCode `OPENCODE`: a pseudo-terminal an agent opens passes the terminal check, so a widening or weakening is confirmed only in a person's own terminal. The guard asks before a command removes one of those variables (`unset`, `env -u`, an empty prefix assignment) or the whole environment (`env -i`).
- 37c0989: The guard now allows by default. Inside the cockpit and its siblings an agent can run ordinary development commands without a prompt: Git work such as commit, merge, rebase, switch, stash, fetch, pull and pushes to work branches, builds, tests, package scripts, interpreters and `gh`. The guard refuses only its blocked list: secrets and credential stores (now including `~/.ssh` private keys, `~/.npmrc`, `~/.netrc`, `~/.config/gh/hosts.yml`, `~/.codex/auth.json`, cloud credentials and `.pem`/`id_*` key files, in every mode, and files named with `--body-file`, `-T` or `@file`), writes outside the cockpit (including `--output`, `curl -o`, `sort -o` and `sed -i`), force pushes, pushes to protected branches, remote branch deletion and rewriting a protected branch, declared hosts, changes to the guard itself (including `git -c` or `git config` keys that choose a program, and `--no-verify`), and privilege escalation. A bare `git push` is resolved to the branch it updates instead of asking. Set `[guards] default = "ask"` to keep the strict mode, where only classified read-only commands, declared commands and allow rules run without a prompt; changing it to `allow` waits for a person's sync.
  
  Two fixes apply in both modes: a `[[guards.allow]]` rule such as `["git", "push"]` no longer admits a push whose destination is unknown or protected, and no allow rule admits a write option that leaves the cockpit or a transfer option that runs a program (`--upload-pack`, `--receive-pack`, `--exec`).
  
  The setup, fix, explain and work procedures now tell agents to report a refusal of a harmless command as a cockpit gap and carry on, and to hand only refusals in the blocked list to the person.
  
  Upgrade: the guard now allows by default. Most `[[guards.allow]]` entries added to work around refusals are no longer needed and can be removed; an allow entry can no longer override a blocked item. Set `[guards] default = "ask"` to keep the previous strict behaviour. A person runs `cockpit sync` after editing `cockpit.toml`.
- 37c0989: The guard recognises a cockpit command by any path that leads into the installed package, however it is spelled: `node ./node_modules/@b00dea/./cockpit/dist/cli.js sync`, another case on a case-insensitive volume, or `node cockpit/dist/cli.js` from inside `node_modules/@b00dea`. Such a command is judged as cockpit, and while `cockpit.toml` holds an unapproved widening edit, any of them that runs `sync` or `upgrade` is refused, as the proven launcher spellings already were.
- 37c0989: More commands that print a credential are refused outright rather than asked about: `gh auth status --show-token`, `gh auth git-credential`, every `git credential*` and `git-credential-*` or `docker-credential-*` helper, `git ls-remote --get-url`, `security find-*-password` with bundled flags such as `-gw`, `kubectl config view --raw`, `gcloud config config-helper`, `aws sts assume-role` and `get-federation-token`, `aws sso get-role-credentials` and `docker compose config`, which interpolates environment files. Variable names holding `PASSWORD`, `TOKEN` or `SECRET` anywhere (`PGPASSWORD`), and `*_PWD`, `*_DSN` and `*_URI`, are judged as secrets. `git remote -v` and reading `.git/config` are allowed again unless a remote URL, an `insteadOf` base or an `http.extraHeader` in the repository's configuration carries a credential.
- 37c0989: More of what `curl`, `wget` and the decompressors write is judged as a write. `curl -w '%output{file}…'` writes that file; `-o` with a `#1` template from a URL glob writes below its directory; `-O` writes the URL's file name in the working directory or `--output-dir`, and `-J` anywhere there; `--etag-save`, `--hsts`, `--alt-svc` and `--libcurl` name files too. `wget` without `-O` writes the URL's file name in the working directory or its `-P` directory, and `-r`, `-m`, `-x`, `-p` or a server-chosen name anywhere below it. `gunzip`, `gzip -d`, `unxz`, `xz -d` and `bunzip2` write the name without the suffix. Writes to `/dev/null`, `/dev/stdout` and `/dev/stderr` through these options are no longer refused as writes outside the roots.
- 37c0989: `curl -K`/`--config` and `wget -i`/`--input-file`, which read their URLs from a file or standard input, ask, and a declared host in a heredoc fed to `curl` or `wget` is refused like one on the command line. Running a file the same call downloads, as in `curl -o i.sh … && bash i.sh` or `chmod +x i && ./i`, asks: download it, read it, then run it in a later call. `go run` of a module path such as `example.test/a/b@latest` asks. Bundled short options such as `curl -fsSo out` and `wget -qO out` are now read as the output files they name.
- 37c0989: `gh release download` and `gh run download` are judged by their `-D` directory: refused when it is a guard directory or the `-p` patterns could match a guard file there, and asked when the file names are unknown and the directory holds guard files, as the cockpit root does. `gh repo clone` and `gh gist clone` are judged by the directory they create. GitHub Copilot's `~/.config/github-copilot`, `~/.vercel`, `~/.netlify` and `~/.heroku` are credential stores. `pnpm -r` and `pnpm --filter` count a script any workspace package declares, read from `pnpm-workspace.yaml` or a `package.json` `workspaces` list. `jq --arg`/`--argjson`/`--rawfile`/`--slurpfile`, `tail -f`, `find … -quit`, a reading command given a glob inside the roots such as `wc -l src/*.ts`, and `base64` are allowed. A Git command or operand writer naming a directory that holds guard files, such as `git restore --source=<rev> .`, now asks instead of being unavailable.
- 37c0989: The guard closes more ways to rewrite a protected branch or publish what Git holds. `git config push.default` and `branch.<name>.merge` writes are refused, a push without a refspec under `push.default=matching` is refused, and one a configured `remote.<name>.push` steers asks. Pushing the stash is refused; `git stash -u`/`-a` is judged like `git add -A`; printing a stash, or patches across every ref, asks. On a protected branch, `git reset` with a mode to any other commit, `git pull --rebase` and a `git pull` that `pull.rebase` makes rebase are refused; `git pull --ff-only` stays allowed. A Git verb that is not one of Git's own commands, such as an alias, asks, `-c help.autocorrect` is refused, and `pre-commit`, `husky` and `lefthook uninstall` are refused as hook removal.
- 37c0989: A `gh api` call that writes, through `-X`/`--method` (attached or not), `-f`/`-F` fields, `--input` or a GraphQL mutation, now asks. One that deletes or force-moves a branch ref, commits a file to a protected branch (`branch=main`), merges into one (`base=main`) or changes a protected branch's protection is refused.
- 37c0989: The guard's own Git queries now read your global Git configuration, from `HOME` and `XDG_CONFIG_HOME` as your Git does, so a `push.default = matching`, a `pull.rebase = true` or a credentialed `insteadOf` set only there is judged: a matching push or a rebasing pull on a protected branch is refused, and `git remote -v` with such a rewrite is refused. Agents cannot write that configuration, since it lies outside the cockpit.
- 37c0989: Under the allow default, an argument holding a command substitution, or a variable this call set to one or to a path outside the cockpit, asks for any program but `echo` and `printf`, and `curl` or `wget` with any expansion asks. A path that climbs out of the cockpit with `..` anywhere in it follows `[guards] external_reads` like an absolute one. `for f in src/*.ts; do wc -l "$f"; done` is allowed when every item is visible inside the cockpit and the body reads each as a read-only command would. `rimraf`, `del-cli` and `trash` are judged as removers, and `corepack` asks, because the guard does not follow the program it runs.
- 37c0989: The generated guard hook registrations for Claude Code (`.claude/settings.json`) and Codex (`.codex/hooks.json`) now state a 30-second `timeout` instead of inheriting each harness's default; on a heavily loaded machine Codex reported a guard call as timed out after 5 seconds. Run `sync` to regenerate them; Codex asks you to trust the changed hooks again.
- 37c0989: Sync binds the guard only to the cockpit installed under the cockpit root: run from any other copy, it refuses with `GENERATED_EXECUTABLE_UNAVAILABLE` and leaves the guard as it was. A root with no installed package, such as cockpit's own development checkout, keeps the module it is already bound to. The guard refuses `node <copy>/dist/cli.js sync` or `upgrade` from a copy of cockpit inside the roots, recognised by its package.json, and asks for any other command run from a copy.
- 37c0989: An edit of `cockpit.toml` that does not widen what agents may do no longer holds every guarded call except `cockpit sync` and `cockpit check` until it is synced. Such an edit grants nothing the last sync did not, so the guard now judges calls under it straight away, and a restriction it adds, such as a new `[[guards.deny]]` rule, is in force at once. The policy pin still applies, and restoring the exact configuration last synced is still admitted. `check` still reports the edit as `GUARD_CONFIG_UNSYNCED` until you run `sync`, which regenerates the files the edit changes. An edit the guard cannot build a policy from still holds every guarded call.
- 37c0989: The allow default now admits the development tools the guard knows, each judged by its own rules: Git and `gh`, package managers and the programs and scripts they run, languages and build and test tools running project files, reading and text utilities, file utilities inside the cockpit, archive and copy tools, `curl` and `wget`, a program the project ships inside the cockpit, and cockpit's own commands. Any other program, such as `ssh`, `kubectl`, `docker compose exec`, `osascript` or `launchctl`, asks, and so does inline code (`python3 -c`, `node -e`, `ruby -e`, `deno eval`, `find -exec`, `awk` calling `system`, `sed` with `e`): a blocked list over a shell is never complete, because a program the guard does not understand can do what the list forbids without naming it. A `[[guards.allow]]` rule admits a program your project needs; it still never admits a blocked command. `ps -o …` no longer counts as an environment dump.
  
  Upgrade: if an agent's work now asks for a program the guard does not know, a person adds a `[[guards.allow]]` rule for that exact command in `cockpit.toml` and runs `cockpit sync`.
- 37c0989: `npm exec vitest -- --run`, `pnpm -r build`, `pnpm --filter web build` and `pnpm --filter web exec vitest` no longer stop the agent. npm hands the program every word after its `--`, wherever that `--` falls, and pnpm's workspace selection runs the program in packages below the workspace root; the guard follows the program and judges it as it would judge it run directly. pnpm with `-C`/`--dir`, or with selection and a path that climbs with `..`, is still refused, because the guard cannot tell where those paths lead.
- 37c0989: The guard no longer holds a call because one of its words is longer than a file name may be. A commit message, search pattern or `echo` argument of 256 or more bytes without a slash made the guard's existence probe fail with `ENAMETOOLONG`, and the call was held as "Guard authority could not be read or revalidated", which read like a damaged installation. Such a word now names nothing, as a missing path does. A path the call names that the guard cannot inspect for another reason, such as a permission error, now holds the call with a message naming that path instead of the guard's authority.
- 37c0989: `git apply` and `git am` are judged by the paths their patch file's headers name, so a patch that rewrites the guard, a hook registration or an environment file is refused like any other write there; a patch read from standard input, or applied with `-p`, `--directory` or `--unsafe-paths`, asks. `unzip` is judged as a write of everything below its destination, like `tar -x`, so extracting into the cockpit root is refused, and `unzip -p`/`-c`, which print members the guard cannot list, ask.
- 37c0989: The guard no longer refuses shell commands that only read `cockpit.toml`. `diff cockpit.toml other.toml`, `sort cockpit.toml`, `pnpm exec cockpit check --config cockpit.toml` and other launcher spellings were refused with advice to use the editing tool, though none of them edit anything. Only a command that can write the file is refused now: a redirect onto it, a writer such as `cp`, `mv`, `tee` or a Git command other than recording one, `sed -i` or `perl -i`, or any program given a write option such as `-o` or `--output`. Its refusal says so and points to the editing tool, through which the guard compares the exact change.
- 37c0989: The guard no longer lets a launcher, a quoting trick or a git subcommand hide the command that runs:
  
  - zsh's `-` precommand is read as a wrapper, so `- git push --force origin main` is judged as the push behind it.
  - A package launcher is followed into the program it runs: `npx`, `npm exec` and `npm x`, `pnpm exec`, `pnpm dlx`, `pnpx`, `yarn exec`, `yarn dlx`, `bunx`, `bun x`, `bun run`, `uvx`, `uv tool run`, `uv run`, `poetry run`, `pipenv run`, and `pnpm <program>`, which pnpm runs as `pnpm exec` when the word names none of its own commands. The launcher is still judged as written, so a rule naming it keeps applying, and the program after it is judged as a wrapped command. A launcher option the guard does not read, such as `npx -c` or `pnpm exec -c`, is refused, as are `npm exec` and `yarn exec` with options after the program and no `--` before it, pnpm options that choose another directory or workspace packages for a program, and `pnpm with`. `npx --no cockpit` and the other cockpit launcher spellings are unchanged.
  - `script`, `flock`, `parallel` and `entr` are refused like `watch`: each runs the rest of its line in a form the guard does not read.
  - `git rebase --exec` (also `-x` and abbreviations), `git bisect run` and `git submodule foreach` are refused with a way forward: git runs their command from the top of the working tree or inside each submodule, not where the guard judges it.
  - A command that sets HOME or CDPATH with quotes inside the name, such as `export HO''ME=…`, or that hands `export`, `declare`, `read` or another variable-setting builtin a name the guard cannot see, no longer gets the hook's HOME or CDPATH applied to its `~` and `cd`. This also holds inside a `sh -c` string.
  - A download piped into `awk`, `gawk`, `mawk`, `nawk`, `nodejs`, `bun`, `deno`, `tclsh`, `lua` or `Rscript` is refused as downloaded code, and so are `deno` given a URL and a launcher whose package is a URL or a Git source such as `github:owner/repo` or `owner/repo`. A package from a registry is judged by the program it runs, as installing a dependency is.
- 37c0989: The guard reads more of what agents write in a shell command, instead of refusing it unread:
  
  - A commit message passed as `git commit -m "$(cat <<'EOF' … EOF)"`, the form Claude Code writes, is judged as the literal message. With an unquoted delimiter the body still expands, so it stays refused, and the reason now suggests quoting the delimiter or `git commit -F - <<'EOF'`.
  - Brace expansion such as `src/{a,b}.ts` or `part{1..3}.md` is expanded into the words the shell runs and each word judged. Nested braces, several expansions in one word, ranges over 256 words, letter or zero-padded ranges, and braces in an assignment or redirect target stay refused.
  - `command -v NAME` and `command -V NAME`, `bash script.sh` (also `sh` and `zsh`), and `sh -c '<literal command>'` are judged as commands. The commands inside a `sh -c` string, and inside any `$(…)` the guard reads, are judged like the rest of the call.
  - `sudo`, `doas`, `su` and `pkexec` are refused with a reason saying privilege escalation is a person's action. A download piped into a shell or interpreter (`curl … | bash`, `wget … | python3`, `gh api … | sh`), `sh -c "$(curl …)"` and `bash <(curl …)` are refused as downloaded code.
  - Commands that run code the guard cannot follow are now refused instead of judged as ordinary programs: `trap`, `let`, `coproc`, `repeat`, `[[`, shells such as `csh` or `tcsh`, programs that run the rest of their line in a form the guard does not read, such as `watch`, `unbuffer`, `chrt` or `taskset`, and builtins handed an array subscript holding `$(…)`.
  - `time`, `caffeinate`, `stdbuf`, `ionice`, `noglob` and `nocorrect` are read as wrappers, like `timeout` and `nice`: the command behind them is judged, and an option the guard does not know stays refused. A wrapper's short option may carry its value attached (`stdbuf -oL`) and plain short flags may be grouped (`caffeinate -dims`).
  - Refusals name a way forward: a glob suggests `rg --files -g` or `fd`, other `command` options name the forms the guard reads, and bare `env` explains that it prints the whole environment, which can hold credentials, and suggests printing one named variable.
- 37c0989: A guard call that has not decided within 25 seconds of starting now refuses itself, exiting 2 with a reason saying the guard ran out of time, instead of running into the agent tool's 30-second hook timeout, whose effect is not measured for every tool. It ends the processes it had started, such as Git, before it exits. Retry the call; a heavily loaded machine slows the guard.
- 37c0989: The guard closes bypasses an independent security review found in the allow default:

  - Cockpit commands its table does not admit, such as `sync` and `upgrade`, ask however they are spelled (`npm run cockpit:sync`, `pnpm --silent exec cockpit sync`, `node --no-warnings …/cockpit.mjs sync`) and whatever an allow rule says.
  - A push or history rewrite that rests on the current branch asks when an earlier command in the same call could have moved it (`git switch main && git push`).
  - Exported variables that steer Git, its hooks or the command search path (`export GIT_DIR=…`, `declare -x GIT_CONFIG_PARAMETERS=…`, `HUSKY=0`, `SKIP=…`, `set -a`) ask, and so do the same prefix assignments, whatever an allow rule says.
  - Protected branches: `heads/main` destinations, `git reset <rev>` and `git update-ref HEAD` on a protected branch, `git rebase <upstream> main`, `git send-pack`, `git update-ref --stdin` and GitHub API writes to a protected or deleted branch are refused or ask.
  - Credential stores: their directories and anything above them (`zip -r ~/.ssh`, `rsync ~/.aws/`), hard links to them or to `.env`, the macOS `/System/Volumes/Data` spelling, and more stores (`.pgpass`, `.gnupg`, `.vault-token`, `.authinfo`, `.config/git/credentials`, Terraform, Cargo, RubyGems, Maven and Gradle credentials, 1Password's config, `*.key`).
  - Commands that print a credential without naming a file (`gh auth token`, `git credential fill`, `git remote -v`/`get-url`, `aws configure get aws_secret_access_key`, `gcloud auth print-access-token`, `az account get-access-token`, `security find-generic-password -w`, `op read`) and environment dumps (`export -p`, `declare -x`, `set`, `printenv`, `ps e`, and variables named with KEY, PASS or PAT) are refused.
  - Assignment values, loop items and unexpanded globs that name or can match a secret ask; any command naming a path outside the cockpit follows `[guards] external_reads`.
  - Glob and magic Git pathspecs and `--cacheinfo` that reach guard controls are refused; `git checkout-index -a` and `git read-tree -u` ask.
  - Abbreviated `--no-verify` spellings are refused.
  - `rsync`, `ditto`, `scp`, `unzip`, `patch`, `uniq`, `split` and similar writers, and `git clone`, `init`, `worktree add` and `bundle create`, are refused when they write outside the cockpit.
  - `git init --template`, `git clone --template` and `git -c` with `init.templateDir`, `diff.external`, `submodule.*`, `trailer.*.command` or `core.alternateRefsCommand` are refused.
  - `/dev/tcp/<host>` redirects count as use of a declared host.
- 37c0989: A search through a package manager's link inside the cockpit's roots, such as `rg -n pattern node_modules/<package>/docs` where the package directory links into a store in the checkout, is no longer refused. The guard follows the link to its target and judges the search there with the same environment-file and secrets walk as any other search; a target outside the roots stays refused. Listing a directory through such a link (`ls`) is still refused.

A copier's or archiver's operand inside the cockpit that leads through a link is refused, since the write would land wherever the link points. `ln -s` to a target outside the cockpit asks, and a link to `/`, `/System/Volumes/Data` or a volume under `/Volumes` is refused as a link to the credential stores below them.

- 37c0989: The guard refuses or asks for more ways to reach a secret, a protected branch or the person's own tools, and admits more ordinary development.

- 37c0989: An edit of `cockpit.toml` that widens what agents may do no longer holds every guarded call until a person syncs. The guard keeps judging calls under the configuration last synced, the copy it already authenticates in `.cockpit/local/guard-config`, so what was allowed before the edit is still allowed and the widened rule is not in force yet. While the edit waits, the guard refuses an agent's `cockpit sync` and `cockpit upgrade`, an edit that would change the pinned policy tables is still refused against the current text, and every refusal ends with a sentence naming the unapproved edit and the exact sync command a person runs. `check` reports the same as `GUARD_CONFIG_WIDENED`. Restoring the recorded configuration out of a widening edit is now admitted, as it is out of any other unsynced edit.
- 37c0989: Git commands that write another revision's files into the working tree are judged against the guard's own files. In a repository whose work tree holds the guard, its hook registrations, the secrets directory or a declared instance, `git merge`, `checkout` and `switch` to a revision, `reset --hard`/`--merge`/`--keep`, `cherry-pick`, `revert`, `rebase`, `stash`, `stash pop`/`apply` and `pull --ff-only` are refused when they would change one of those files, and ask when the revision does not resolve or an earlier command in the call could change it. Any other `git pull` there asks, since what it brings is unknown until it is fetched: fetch first, then `git merge --ff-only <remote>/<branch>`. `git am` of a mail whose body is base64 or quoted-printable, or of a file that names no path, asks.
- 37c0989: `selftest` runs with one command: `cockpit selftest --config cockpit.toml --interactive`. With no `--probe-specifications`, it writes fresh probe specifications for that run to a new file under the ignored `.cockpit/local/probes`, shows the same approval as before, bound to that file's digest, and runs. Each run writes its own file, so one from before an upgrade or a `cockpit.toml` edit is never reused. Without `--interactive`, or with `--json` or in CI, it still refuses and writes nothing. Keeping specifications under review in your tree works as before with `--write-probe-specifications` and `--probe-specifications`.
