# @b00dea/cockpit

What changed in each release of cockpit, newest first, for someone deciding whether to upgrade:
what breaks, what to do about it, and what is new. Changesets writes each entry from the
changesets merged since the previous release. An entry that needs more than `cockpit sync` ends
with a line starting `Upgrade:`; the [changeset guide](../../.changeset/README.md) defines that
convention.

Versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). The public surface a
major version protects is the CLI's commands and flags, the <!-- cockpit:ref consumer=cockpit.toml --> `cockpit.toml` schema, the generated
file layout, and the overlay contract. Deprecation and migration rules are in the
[release policy](../../docs/release-policy.md).

## 0.1.4

### Patch Changes

- ae67d7a: Correct the Varlock guidance with measured behaviour. `--redact-stdout` does not cover Varlock's own errors, which can print source lines and a failing resolver's command and stderr. Env files are evaluated when loaded, so a migrated value holding `$(...)` runs a command, even in double quotes; only single quotes keep it literal. Cockpit's schema probes already keep only key names and status, and their behaviour does not change.
- ae67d7a: A refusal naming a stack's hold now says its process may only be unconfirmed, and asks you to check `ps -p` before the `kill` it suggests, because a pid can have been reused. Cleaning up an attempt also clears week-old socket files that a crash left in cockpit's private temporary directory.
- 450ff5d: Fix races in fenced execution that could run a cancelled action or leave an attempt stuck on "repair required".
  
  - An executor that started late could still run its action after that attempt's cancellation was certified and cleaned up. It now refuses.
  - A stop acknowledged before the action was released was dropped, so the action still ran. It now never starts.
  - An attempt stayed stuck when its supervisor was killed for losing the marker race, when the executor died after publishing its marker, or when a marker landed although publishing it reported failure. Each of these now repairs normally.
  - A second recoverer, or an executor that died late, could leave a marker the state inventory refuses. Neither does now.
- ae67d7a: Publish new measurements in the capability matrix. Claude Code's committed and local `additionalDirectories` lists combine in a trusted workspace, so a worktree grant no longer needs a person. Claude Code, Codex and OpenCode each list the generated skills, and OpenCode lists the generated evaluator. Workspace trust does not make Claude Code load a sibling guide through `additionalDirectories`. OpenCode exits 0 with no failure when a plugin has a syntax error or throws, so a guard plugin that fails to load reports nothing.
- ae67d7a: Say what a sandbox withholds. A `ps` that cannot report a process start now points at a sandbox, because macOS's Seatbelt refuses to run `/bin/ps`. With `[browser]` declared, `check` now reports an unreachable state root as `STATE_ROOT_UNAVAILABLE` rather than `SURFACE_INPUT_INVALID`. The setup procedure no longer says state is out of reach in Codex's sandbox when its directory can be granted alone, and it reports generated configuration, machine readiness, hook enforcement and live proof separately.
- ae67d7a: Allow an existing private state directory to work under a narrowly scoped sandbox write grant
  without also requiring writes to the home directory and other ancestors. Missing state directories
  still require write access where creation starts, and unsafe ownership, symlinks and denied writes
  remain refusals.

## 0.1.3

### Patch Changes

- 8677d16: Check Codex hook discovery against the original checkout before checking trust in linked worktrees. Report missing or different source hooks separately, and name the actual source when matching hooks need human trust review.
  
  Upgrade: if a linked worktree reports CODEX_HOOK_SOURCE_MISMATCH, review and roll out matching hooks in the original checkout, then trust that source in interactive Codex.
- 091bc20: Under `[work] grading = "checks"`, acknowledging a test weakening is a person's or CI's step even where `[work.gates] acknowledge = "agent"`, because no model reads the change and the acknowledgement alone passes the `test-protection` check. An agent's `work acknowledge` there is refused with `WORK_PERSON_REQUIRED` unless the gate is `ci`, and an acknowledgement the agent recorded under another grading mode no longer passes the check. Under `independent`, `subagent` and `self` grading the field works as before.
- f4233e2: Avoid stale-directory findings for bare inline identifiers that name tables or APIs. Docs check still reports explicit directory paths, relative links and deleted bare file names.
- 45e44a4: Clarify MCP approval recovery guidance: enabling or changing server approvals and widening tool access require a person under the default policy, while agents may remove unchanged approvals and add or narrow exact tool allowlists. Guard enforcement is unchanged.
- 5c916fe: `doctor` and `check` now check Codex hook trust against the hooks file Codex actually loads in a bare repository's worktree, a submodule, a checkout with a separate Git directory and a cockpit root outside Git: the directory's own `.codex/hooks.json`. They used to report `CODEX_HOOK_UNTRUSTED` as unverified in those layouts, which no trust could clear. A linked worktree whose shared Git directory is named `.git` still sources its hooks from the original checkout.
- aba9b01: Let a team hand two more process gates to the agent, both still a person's by default. `[autonomy] confirm_answers = "agent"` lets `cockpit confirm` confirm `cockpit.name`, `estate.runnable` and `environment.test_data`, and records the confirmation as the agent's decision under that field; trust decisions stay a person's. `[autonomy] instruction_files = "agent"` lets the guard admit `setup --write-instruction-files` and `--write-instruction-pointers`. Safety and autonomy now classifies every gate as a guardrail or a process gate, shows the shipped, stricter and most agentic setting for each, and gives a fully agentic `cockpit.toml` that keeps every guardrail.
- c0131f2: `sync` now writes a tool list into Claude Code's evaluator subagent definition: `Read`, `Grep`, `Glob` and exactly the browser tools the cockpit lets Claude Code call (every tool of the `playwright` server, or those `[mcp.allowed_tools]` lists for it). Claude Code refuses the subagent's file writes and shell commands, so under `[work] grading = "subagent"` its read-only is enforced there; the capability matrix records the measurement. Codex and OpenCode definitions are unchanged, and the verdict the working agent relays is still its word.
- faa9132: `sync` and `check` no longer spend time describing every byte of a generated file they read, which took about 67 ms for each 128 KiB.
- 121c2b3: Allow `cockpit env schema --replace-from` to create the first schema in an existing sibling component directory with a regular Git-tracked product file directly inside it. Secret files, protected locations and links cannot authorize a component. Creation does not stage the schema or run its resolvers; discovery requires Git tracking and validation still requires a commit.
- bd1a125: Recognize numbered decisions, possessive clauses, "only for" qualifiers and a clause-qualified
  record listed after a whole one as partial ADR supersessions in `docs check`. Keep the original
  record accepted when only part changes, and avoid treating incidental guide paths as missing ADRs
  while still checking record references.
- d834631: `[work] grading` gains two choices, so every way of grading is supported and documented. `subagent` records a verdict the working agent relays from a read-only subagent it spawned, closes as `subagent-reported` and says cockpit cannot verify it; with nothing submitted, `work grade` runs a separate evaluator instead. `off` makes the grader optional: orders are tracked and close as `ungraded` whatever their checks showed, with those facts kept on the record. Moving to either from a stronger mode needs a person, as moving to `self` does.
  
  `init` now asks `work.grading`, proposing a value from the listed tools it finds on `PATH` with its reason. An answers file that omits it stops at that question. Existing cockpits keep their value. `doctor` now reports whether `independent` or `subagent` can run here once a `workorders/` directory exists or `cockpit.toml` sets `[work] grading`, and no longer warns about evaluators under `checks`, `self` or `off`. A grade by the tool running the command, with no other tool passed over, now warns (`EVALUATOR_IS_RUNNING_TOOL`).
  
  `work signoff` no longer closes an order as done on a grade made under a weaker mode than the one now in force, and `work verify` reports such a closure.
  
  An answers file can be written by an agent, so `init --answers` now records every trust answer it supplies (`sibling`, `environment.install_policies`, `environment.posture`, `testing`, `guards`, `work.grading`) under `unconfirmed`, whatever its `[provenance]` claims. While `work.grading` or `environment.install_policies` waits there, the stronger default holds: grading runs as `independent`, and the guard admits no install policy's build or test command. `doctor` and `work status` say what is held; a person confirms by deleting the entry and running `sync` in a terminal.
- 8a36a40: The guides are shorter, with each fact on one page. The README no longer claims that `cat .env.example` works under Claude Code: use `cockpit env keys` and `cockpit env schema`. The adoption skill no longer says the package is missing from npm.

## 0.1.2

### Patch Changes

- 28dc303: Add `cockpit env keys`, which lists the variable names environment schemas and templates declare with no value and nothing resolved, and `cockpit env schema`, which prints one `.env.schema` verbatim or, with `--replace-from <draft>`, replaces it atomically. An agent runs them without a prompt, so it no longer depends on files a native secret denial refuses. A draft that could hold a secret is refused, so a replacement cannot launder one out through `env schema`.
- ed50cbc: Validate env schemas the way they are documented. The probe adds `env/.secrets/<cockpit name>/<slug>` as a second `--path` when it exists, checks every tracked `.env.schema` in a sibling and the cockpit root's own, reads the checkout `cockpit use` serves, finds a linked worktree's gitignored store in its main checkout, and ignores inherited `_VARLOCK_*` variables. Only the required-empty message means missing. Any other key error, such as a signed-out or unreachable secret provider, makes the row unavailable with a sign-in remedy, where it used to read as an invalid key. Keys the caller's shell satisfied raise the new `ENV_SCHEMA_OVERRIDDEN` warning, and a missing Varlock is a recommended readiness gap, not a required one.
  
  `doctor` and `preflight` run a schema's resolvers, so review schema changes as you review code.
- ed50cbc: Let local MCP declarations name optional caller environment overrides without requiring them at startup. Unset and empty values stay distinct, undeclared variables stay out of the server, and the optional names are part of what an approval covers.
- ed50cbc: Add `[mcp.allowed_tools]`, exact allowlists per MCP server. Codex receives `enabled_tools`; Claude Code receives an authenticated guard scoped to the restricted server namespaces, which denies unlisted tools and leaves listed tools to Claude Code's own permission prompts. Harnesses with no restriction mechanism omit a restricted server and report `MCP_TRANSPORT_UNAVAILABLE`.
  
  MCP tool input is bounded at 1 MiB, separately from the smaller shell and edit limit. Browser rebinding keeps restrictions, and the browser skill names only allowed tools. A restricted server whose native namespace overlaps another server's is refused.
  
  A dotted name works under Claude Code, which calls `read.record` by the name `read_record`. It cannot tell those two apart, so a listed `read_record` also admits a server tool named `read.record`; Codex matches the raw name. Tool restrictions do not filter MCP resources or prompts and do not make an unsafe allowed dispatcher safe. A name, a token scope or `readOnlyHint` is not an enforcement boundary.
- ed50cbc: Run read-only observations through bounded absolute `PATH` entries. Empty, dot and parent-relative entries are excluded for `sync`, `check`, `doctor`, `preflight` and `docs check`, so a poisoned working directory never runs and a package manager's relative entry no longer stops them. Guards, sessions, evaluators and MCP startup keep their exact `PATH` authority, a noncanonical absolute entry still refuses and nothing is normalized. `MCP_COMMAND_UNRESOLVED` names the excluded entry and asks for `PATH` to be fixed rather than the declaration re-approved. Git child processes in these observations no longer run a configured fsmonitor.
- ed50cbc: Make pnpm installs work and their diagnostics accurate. A package link is accepted only when it resolves to the exact cockpit copy running. `COCKPIT_LAUNCHER_UNPROVEN` names the route the guard can prove, the package's `bin/cockpit.mjs`, instead of pnpm's shell shim. `COCKPIT_NOT_INSTALLED` says when another copy is running and names both. Install commands in these refusals follow the lockfile present, and `sync` and `check` accept a `file:` pin that pnpm links and `pnpm-lock.yaml` resolves.
- ed50cbc: Let agents apply proven reductions in authority without a person: revoking an unchanged MCP approval, removing a command grant, adding a denial, and adding or narrowing a tool restriction. New or changed approvals, expanded command access, gate authority and removing a restriction stay with a person. While `mcp_approve = "agent"`, an agent's `[mcp.approved]` edit is no longer held, and removing a tool restriction still is.
  
  An MCP restriction now applies under `stale_delete = "person"` or `"ci"`: `sync` removes an unchanged MCP-only file of a listed tool without that approval, while a hand-edited file stays a conflict. An agent can undo an edit `sync` refused: the `GUARD_CONFIG_UNSYNCED` hold admits one edit that restores the recorded configuration byte for byte, however the edited file fails to load. An edit that widens stays held for a person. Hold messages now name what a hold stops, which is shell commands, file edits and writes, and restricted MCP tools under Claude Code.
- ed50cbc: Protect `.secrets` directories at any depth, and make the tracked-secret check agree with the guard: `.env.schema` is no longer reported, while `.env.dist` and tracked files below a `.secrets` directory are, and a declared environment template stays exempt.
  
  Upgrade: the generated ignore block now covers `.secrets` contents everywhere, so existing cockpits report it as drift until the next `sync`. The guard now denies `git add` of a directory, or `git add .` in a managed repository, whose tree holds a `.secrets` directory, where it used to ask. Stage explicit paths instead. A `.env.dist` that holds no secrets can be declared as an environment template to clear the new report.
- ed50cbc: Let `init` accept an explicit empty Compose list for staged adoption of a runnable product, keeping install policies, testing, guards and answer provenance while skipping runtime questions. Supplied answers that become irrelevant are reported.
  
  Upgrade: `init` on a cockpit that declares no runtime now ends at stage `surfaces-verified`, where it reported `environment-verified`, because nothing verified an environment. A script that reads `result.stage` must accept the new value. Such a cockpit reads its schema status from `cockpit doctor`. Interview state already recorded at the old stage stays valid.
- ed50cbc: Bind surfaces-only `sync`, `check` and `doctor` to one checkout identity in linked worktrees and nested configuration directories, and keep publication working where only setup needs to be strict. A plain `git status` no longer refuses `sync` or `check`, and a repository-local include is accepted. A `.git` entry Git rejects, or Git missing from `PATH`, publishes as standalone with a `GENERATED_CHECKOUT_STANDALONE` warning that says the guard needs a readable repository and holds guarded calls until it has one. A checkout observation interrupted by Git activity retries, then says so, instead of reporting unsupported configuration origins or an invalid worktree inventory.
- 28dc303: `preflight` and `doctor` no longer run Varlock on a schema Git does not show as committed and unchanged, because loading one runs its resolvers. Such a schema keeps the row passing and warns with `ENV_SCHEMA_UNCOMMITTED`.
- ed50cbc: Make environment access an explicit setup decision even without a schema. `init` and `doctor` recommend Varlock with `ENV_SCHEMA_UNDECLARED` when a root holds dotenv or template files and no `.env.schema`, reading file names and types only, within a bounded scan. Every cockpit Varlock probe and setup or recovery command sets `VARLOCK_TELEMETRY_DISABLED=true`, and raw Varlock diagnosis stays with a person while agents get key names and validation only. Existing scoped authorization is reused rather than asked for twice.
  
  The environment-file denial now points at a command that runs: an agent uses a declared project command that wraps Varlock, and a person in a terminal runs it without `--redact-stdout`, which Varlock refuses there. The documented Claude Code shell workaround for dotenv documentation files was disproved and removed; those files stay denied under the broad secret rule until a safe replacement passes native probes.

## 0.1.1

### Patch Changes

- 88f97b6: Browser route findings are evidence, not a gate. `browser drive` with findings now exits 0 and carries `verdict: findings` with the full receipt; `--fail-on-findings` restores exit 2 (`BROWSER_ROUTE_FINDINGS`) for a criterion that wants a clean route. Each route also carries an `excerpt` of up to five console and uncaught error messages, 240 bytes each, tagged `untrusted-page-content`, so a favicon 404 can be told from a broken API call. The excerpt is read only when `[browser.data]` is isolated, not restored and not reaching production; otherwise it is omitted with the reason.
  
  `browser.request_preapproval` now defaults to on when `[browser.data]` qualifies for it and to off otherwise; an explicit value still wins, and `true` on a posture that does not qualify is still refused.
  
  The command after `cockpit exec --service <s> --` runs in the container's filesystem, so the guard no longer proves it read-only: it stays subject to the name-based denials and is admitted only by a `[guards] allow` rule or a declared build or test command, and otherwise asks.
  
  `init` lists the `COMPOSE_IMAGE_TAG_SHARED` finding beside the other Compose findings.
- 6058a69: `browser drive` now reports what each route's page did wrong, not only that it loaded: console errors, uncaught page errors, and failed or 4xx/5xx requests to the application's own origin, with method, URL path (no query) and status, plus counts of warnings, aborted requests and third-party traffic. Each route gets a `clean` or `findings` verdict, at most 20 entries are kept per route, and message text, bodies, headers and cookies are never read. With `--fail-on-findings` a drive with findings exits 2 with `BROWSER_ROUTE_FINDINGS`, so it works as a work-order criterion check that demands a clean route; without it the findings are evidence and the drive exits 0. `--route <name-or-path>` drives or captures a single declared route.
- 1752c64: `cockpit check` now refuses a Compose service that sets `container_name`. Docker allows one container
  of a name, so the second checkout's `up` failed at runtime, which breaks the one-stack-per-checkout
  promise; the finding is `COMPOSE_CONTAINER_NAME_FIXED`, an error like `COMPOSE_PORT_NOT_LEASED`, and
  `init` shows it beside the drafted `cockpit.toml`. The install instructions now name the pnpm and
  yarn equivalents.
  
  Upgrade: remove `container_name` from each Compose service `check` names and address the service by
  its Compose service name or `docker compose exec <service>`.
- 1cd11c3: Compose profiles now activate. `[environment] profiles` lists the profiles every `up` and `session`
  starts, and `up --profile <name>` (repeatable, also on `session`) adds more for a run. The stack
  records its profile set, so `down`, `sleep`, `logs`, `preflight` and the service verbs act on the
  same services, and a `profile:<name>` sibling is mounted while its profile is active. A profile no
  service declares is refused with `COMPOSE_PROFILE_UNDEFINED`; adding a profile to a running stack
  is refused like any other change, so run `down`, then `up --profile <name>`.
  
  New service verbs act on this checkout's own stack without naming its Compose project: `ps`,
  `restart --service <name>`, `rebuild --service <name>` and `exec --service <name> -- <command>`.
  The guard admits them like `up`. The command after `exec --` runs inside the container, where the guard cannot see files, so it is never treated as read-only: it runs without asking only when a `[guards] allow` rule or a declared build or test command matches it. An agent's `--profile` runs without asking only for a profile in `environment.profiles` that mounts no operator-gated sibling.
  
  `check` refuses a built service with a fixed `image` tag (`COMPOSE_IMAGE_TAG_SHARED`), because one
  checkout's build replaced the image another checkout's stack ran, and now judges bind mounts of
  profile-gated services under their profiles instead of refusing them.
  
  Upgrade: run cockpit sync, so Claude Code may run the new verbs without asking.
- e7da68a: `cockpit confirm <answer> --config <file>` clears an `unconfirmed` entry once the observation that verifies it passes on this machine: `preflight` with the stack up for `ports.bases`, `check` for `environment.compose_files`, and the measured runtime against the declared floor for `environment.machine`. It removes only that entry from `cockpit.toml`, keeping comments, and records what ran, when, the result and an evidence digest in `.cockpit/local/answer-confirmations`, which the guard keeps agents from writing. The guard treats the removal as non-widening only while that record matches the configuration, so an agent's own sync applies it where `[autonomy] sync = "agent"`; a missing, stale or forged record still holds it for a person. A failed observation is refused with `CONFIRM_OBSERVATION_FAILED`, and the trust decisions (`guards`, `testing`, `environment.install_policies`, `sibling`, `environment.posture`) and the answers no observation settles (`cockpit.name`, `estate.runnable`, `environment.test_data`) with `CONFIRM_PERSON_REQUIRED`.
  
  `DECLARATION_UNCONFIRMED` now names `cockpit confirm` for the answers an observation settles and says a person confirms the rest.
- 55fca43: New `cockpit docs check` command and `[docs]` table. `living` lists globs of documents that must stay true, in the cockpit's repository or `<sibling slug>:` in a sibling; the command reports `DOCS_REFERENCE_REMOVED` for a path a living document cites that the repository history deleted or renamed (naming the new path), and `DOCS_TARGET_REMOVED` for a `make` target a Makefile once defined and no longer does. A path or target that never existed is not reported. The optional `decisions` and `decisions_index` keys check a decision-record set: `DECISION_NUMBER_REUSED`, `DECISION_UNINDEXED`, `DECISION_INDEX_ENTRY_MISSING`, `DECISION_STATUS_MISSING`, `DECISION_LINK_UNRESOLVED` and `DECISION_SUPERSEDED_STALE`. It exits 2 on any finding, supports `--json`, refuses with `DOCS_NOT_DECLARED` without a `[docs]` table and reports `DOCS_DECLARATION_UNMATCHED` for an entry that matches nothing. The guard admits it for agents because it only reads, the generated Claude Code settings allow it without a prompt, and `doctor` names it when `[docs]` is declared. Run `cockpit sync` to pick up the new allow rule.
- 33e2085: Every Git command cockpit runs now carries `core.fsmonitor=false` and `core.hooksPath=/dev/null`, including the `ls-files` and `log` reads behind `docs check`. `pull` skips a checkout whose own Git configuration sets `core.sshCommand`, `core.askPass`, `core.gitProxy`, `credential.helper` or a remote's `uploadpack`/`receivepack`, as `PULL_SKIPPED` naming the key, because the fetch would run that command.
  
  Browser console and error excerpts are redacted like other diagnostics and lose URL query strings and fragments before they are kept as evidence. `docs check` redacts Git's error text in its diagnostics.
- c5ea35d: Grading now detects a change that weakens tests: deleted test files, skipped or focused tests, suppressed checks, removed or loosened assertions, and narrowed test configuration, judged against the order's recorded base commits. Under `checks` grading such a change fails until it is acknowledged with the new `work acknowledge` command (`[work.gates] acknowledge`, default `agent`); under `independent` and `self` grading the findings are judged as the `test-changes-justified` criterion instead. `[testing] test_files` declares which files are tests; common layouts are the default.
- 0fdaf04: The guard's pin on `[work]`, `[work.gates]` and `[autonomy]` now judges the command after `cockpit exec --service <s> --` as a command of its own, as it already did for `cockpit session`. Before, a container command that named `cockpit.toml` after its own `--config` was taken for cockpit's `--config` operand and let through. Because the command runs in the container, no read-only spelling excuses it from the pin either.
- 69a3d9a: `sync` refuses a sibling guide that is, or links to, a `.env` or `.env.*` file, a file below a
  `.secrets` directory or a declared environment instance, with `PROJECTION_GUIDE_SECRET`, instead of
  copying its contents into the root `AGENTS.md` that every agent reads.
  
  The guard admits `up --profile <name>` and `session --profile <name>` from an agent only for a
  profile already in `environment.profiles` that mounts no sibling with `gate = "operator"`; any other
  profile asks for a person.
- e17d668: An agent can now apply its own `cockpit.toml` edit when the edit does not widen what agents may do.
  After any edit the guard still holds every tool call, but it compares the edit with the configuration
  the guards were generated from: when the edit only rewords a sibling's purpose, moves a port, adds a
  derived route, an agent tool or an operator gate, or removes a Compose file, profile or resettable
  volume, the guard admits `cockpit sync` and `cockpit check` from the agent (where `[autonomy] sync =
  "agent"`) and reports `GUARD_CONFIG_UNSYNCED`. Any other edit keeps the person-only hold, whose
  message now names each field that widens: any change to `[guards]`, `[work]`, `[autonomy]`, `[mcp]`,
  `[testing]` or `[browser]`, a new sibling, a sibling's changed directory, guides or environment files,
  a command field, and a field the classification has no rule for. `check` reports the same
  classification, `GUARD_CONFIG_WIDENED` as an error and `GUARD_CONFIG_UNSYNCED` as a warning. Sync
  keeps the configuration it generated the guards from in `.cockpit/local/guard-config`. An agent may
  now run `cockpit tool add`; `tool remove`, `sibling add` and `sibling remove` stay a person's.
- bf769dc: `init` now lets the setup agent accept what it read from exact sources. Each proposal in `interview.outstanding` carries `provenance.kind` (`derived`, `measured` or `inferred`) and each field a `confirmedBy` of `agent` or `person`. An answers file can mark `cockpit.name`, `ports.bases` and `environment.compose_files` as `"derived"`, with or without a value: init answers with the value it read, refuses a different one with `DOCUMENT_CONFIGURATION_ANSWER_NOT_DERIVED`, and records the source file and line in `cockpit.toml` and `result.derived` instead of listing the field as unconfirmed. The defaults digest now covers only the security boundaries (protected branches, guard allow and deny lists, approved MCP servers, resettable volumes, generated host paths), and the draft shows which values a person confirms. The machine floor is proposed: memory and CPUs from the Compose file's service limits, or from this machine's measured container runtime where no limit records them; free disk and cold start are never proposed.
- 4c96d73: Add `cockpit stacks`, which lists every stack on this machine with its checkout, state, containers,
  volumes, port lease and last activity, and `cockpit stacks prune`, which previews and, with `--apply`,
  removes the stacks whose checkout is gone, such as a deleted worktree's, together with their
  containers, networks, labelled volumes, port lease and state. A checkout is proven from Compose's
  working-directory label or from the checkouts Git records for the cockpit, never from names; a stack
  whose checkout exists is never touched. State this version cannot read is listed and kept, except
  state folders in the spelling an earlier build used, which are pruned once none of their stacks is
  kept. A prune that deletes volumes follows `[autonomy] reset`; otherwise a person approves it with
  `--interactive`. `doctor` now warns with `STACKS_ORPHANED`, and its warning
  about unreadable state folders names `stacks prune` instead of a manual `rm -rf`.
- 98b824a: A `.cockpit/policy.json` written by 0.1.0, which has no `[work.gates] acknowledge`, no longer makes every `work` command, `sync` and `doctor` refuse it as malformed: a missing decider is read as `person`, so the new `agent` default is reported as the weakening `work.gates.acknowledge: person -> agent`, which a person accepts with `sync --interactive`. A record with an unknown key still refuses, and now says what to do when the committed copy is the damaged one. A grade that finds an agent's amendments lower the bar stays on the order until a person or CI amends it, so a later `work check` no longer lets the agent amend again. Two concurrent `work recover --apply` runs no longer both take over a dead lock and delete each other's: one takes it over and the other refuses. `work decide` writes decision records and the index line through descriptors checked against the confined path, so a directory swapped for a link while the record is opened no longer redirects the write outside the repository.
