Initial public release.

- One `cockpit.toml` is the policy and the product declaration: sibling repositories, ports, guards, MCP servers, autonomy and work. `cockpit sibling add|remove` edits the repository list and `cockpit tool add|remove` edits `[surfaces] tools`, which defaults to Claude Code, Codex CLI and OpenCode.
- `cockpit sync` writes the matching instructions, skills, subagents, hooks, permissions and MCP entries for each listed tool, with `--dry-run` previews, and `cockpit check` fails when a generated file no longer matches, locally or in the `cockpit-check` GitHub Action. `sync --adopt <path>` moves a team's existing agent settings file into cockpit and merges it with the generated version.
- One guard policy refuses pushes to protected branches, reads and edits of declared environment files and secrets directories, and commands against declared hosted databases or vendor hosts. `[[guards.deny]]` and `[[guards.allow]]` add your own command rules. The hook is installed for Claude Code, Codex CLI and OpenCode, fails closed, and also denies agent writes to `.npmrc` and to cockpit's own policy and records. Codex runs the hook only after a person trusts it once per machine; `doctor` and `check` report `CODEX_HOOK_UNTRUSTED` until then. `cockpit selftest` checks that each tool enforces the generated controls, and the capability matrix records dated measurements.
- Sibling repositories' guides are copied into the root instructions, and the Claude Code and Codex hooks run `cockpit check` as a session starts.
- `cockpit init` starts in the repository it runs in: a single product repository gets an in-repo cockpit, every listed tool gets the `cockpit-setup` skill, and the interview marks every value it inferred or defaulted. `init` writes a commented `[work.gates]` and `[autonomy]` block, and `--registry` turns an existing shell-script setup into a draft. `init --scaffold-compose` writes one plain `compose.yml` for a small app, once.
- cockpit runs your own Compose files and generates none. `setup`, `up`, `session`, `sleep`, `down`, `reset`, `preflight`, `doctor` and `logs` run the stack on your live checkouts, with port leases and holders so one agent cannot stop another agent's stack. `environment.seed` with `resettable_volumes` fills and refills the data, and `reset` needs a person by default. `down` and `reset` use only a local Docker context, and `cockpit runtime measure` records the local runtime for this machine only.
- `[autonomy]` and `[work.gates]` say who may pass each step. Everything defaults to `agent` except `[autonomy] reset = "person"`. `check` and `doctor` report a policy weakening nobody has confirmed, and the guard denies an agent's edit of the policy.
- Each repository's tracked `.env.schema` is validated with Varlock when it is installed, without reading values. MCP servers are enabled only for the digest recorded under `[mcp.approved]`.
- Work orders are `workorders/<id>.md` with YAML front-matter. `[work] grading` is `independent` (an evaluator in the first usable of `work.evaluators`, any of Claude Code, Codex CLI or OpenCode, reruns the checks and grades each criterion), `checks` or `self`. `cockpit grade --criteria <file>` grades uncommitted work with no order, and `work verify` checks the records in CI.
- Declared test stages and gates run with `cockpit test-run`, and only a complete passing gate reports PASS.
- `cockpit browser drive` and `browser screenshot` visit the application's declared routes with a local browser. `browser.endpoint` may name a loopback browser service from your own Compose file, which publishes the Playwright MCP declaration and the `cockpit-browser` skill. cockpit runs no browser service and no debugger.
- `cockpit upgrade [<version>] [--dry-run]` moves the exact pin and re-runs `sync`.
- Teams share one cockpit: the root `package.json` pins the exact cockpit version, `check` refuses a different running version, and cockpit manages its own block in `.gitignore`.
- Diagnostics name what failed, why it matters and the fix. The package ships the user guide under `docs/` and skills that tell agents how to set up, explain, fix and work in a cockpit; install the adoption skill with `npx skills add b0dea/cockpit --skill adopt-cockpit`.
- Runs on macOS and Linux. Native Windows is refused at startup; WSL2 should behave like Linux but is untested.
