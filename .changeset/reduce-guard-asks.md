The guard asks far less. Under the default `allow` mode a command now runs unless it names a secret, a declared host, a guard file or a protected branch push; unknown programs, inline code, variables, globs and reads the guard cannot prove run as a project script does. A person is still asked before container commands, merges and releases, `git clean`, and pushes or Git writes the guard cannot resolve.

Sessions started in a cockpit subdirectory now get the Read and Edit deny rules too, in the local settings that carry the hook. Agents can stage the guard script exactly as the last `sync` recorded it, so an upgrade can be committed; other guard files are refused with the `!` command a person runs.
