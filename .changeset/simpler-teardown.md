`sleep`, `down` and `reset` finish what an interrupted run left when you run them again.

**Changed:** each takes a lock on the stack, stops it, reads what Docker reports now, removes this stack's resources by id, and reads Docker again to confirm they are gone. If one is interrupted, run the same command again: it removes only what is still there. A lock left by a killed command is taken over by the next one. If a container of the stack appears while `down` or `reset` runs, as a leftover `docker compose up` can start one, the command refuses and keeps the stack and its ports; run it again. While one runs, another refuses with `STATE_LOCKED` and `up` refuses to lease the stack's ports. A state lock left by a command killed while taking or releasing it is now taken over by the next command, as one left by a killed holder already was, and a lock no longer stays quarantined until a person removes it. A stack's lifecycle progress, whether it has come up, and when its seed last succeeded now live in one record; `setup` no longer writes lifecycle state. A stack started by an earlier cockpit reads as not yet up, so `preflight` treats it as before its first bring-up until the next `up`, which runs the seed once more. A listener on a leased port that no cockpit session started is now a `PORT_FAMILY_COLLISION` warning beside a passing check, not a failure, and is identified from one read of the sockets and processes. An approved `reset` refuses with `RESET_CONFIRMATION_MISMATCH` when the stack changed after its preview; run it again to approve the current targets.

**Removed:** the detached supervisor that tracked a removal in progress, and the refusal that asked for an interrupted attempt to be repaired by hand. Ctrl-C or SIGTERM during `sleep`, `down` or `reset` now ends the step it started and waits for it before exiting; only a step left by SIGKILL keeps running, and the next run no longer stops it. `stacks --json` no longer reports `state.draining`.
