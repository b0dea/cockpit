The guard now judges a recursive copy (`cp -R`, `-r` or `-a`) as it judges `rsync`, instead of refusing it as a form it does not model. Each source is read as a tree, so copying one that holds an environment file, a `.secrets` directory or a credential store is refused, and each destination is a write, so copying into a guard control, the installed cockpit or a related checkout is refused. Copying a tree that holds guard files or a checkout's `.git`, such as `cp -R . build/snapshot`, asks, as `rsync` does. A call may now end in one command that makes or copies links, as in `mkdir -p build && cp -r src build/out`, since nothing after it can follow them. A glob source such as `src/*` is now walked as its directory for `cp`, `rsync` and recursive searches alike, where the walk used to find nothing. A credential store's directory spelled with a trailing slash or a glob after it, as in `rsync -a "$X/.aws/" build/` or `glob('.aws/*')` in inline code, is now refused as the directory itself. Shell text that a tmux or screen session, an `at` or `batch` job, `xterm -e` or osascript's `do shell script` runs is now judged as shell the guard does not read: refused when it names a secret, a credential or a guard file, and otherwise asked, where before it ran unread.
